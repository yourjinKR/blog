## 개발 내용

### AI 추천 결과를 운동 데이터에 연결

AI가 반환한 운동명을 서비스의 운동 ID에 매핑하고, 추천 결과를 루틴 저장 요청으로 변환했습니다.

- 정확한 이름을 먼저 찾고, 실패하면 공백 제거·한글 자모 정규화·편집 거리로 유사 후보를 탐색했습니다.
- 운동 ID와 세트 수·무게·횟수를 기존 루틴 저장 구조로 변환했습니다.
- 응답 구조·분할 수·운동 식별자를 검사하고, 알 수 없는 값을 API 로그의 예외 사유로 남겼습니다.

[운동명 매칭](https://github.com/juhyeon2398/soldeskProject2/commit/95c40bf) · [루틴 데이터 변환](https://github.com/juhyeon2398/soldeskProject2/commit/1941c4b)

### 결제수단 삭제와 예약 취소 연동

결제수단 삭제 시 외부 예약 취소 결과를 확인한 뒤 로컬 주문과 결제수단을 정리하도록 처리 순서를 구성했습니다.

- 연결된 예약 주문을 조회하고 PortOne에 예약 취소를 요청했습니다.
- 응답의 `revokedScheduleIds`와 주문의 `schedule_id`가 일치할 때만 `CANCELLED`로 변경했습니다.
- 빌링키 삭제 성공을 확인한 뒤 로컬 결제수단을 삭제하고, 내부 실패 시 DB 변경을 롤백하도록 했습니다.

[구현 커밋](https://github.com/juhyeon2398/soldeskProject2/commit/a32f722)

### 예약 결제 상태 조회 배치

PortOne의 예약 처리 상태를 로컬 주문에 반영하고, 결제 성공 시 다음 예약을 조회·생성하는 배치를 구현했습니다.

- 매일 00:10에 한국 날짜 기준 당일 `READY` 주문의 외부 상태를 조회하도록 구성했습니다.
- 확정된 외부 상태를 로컬 주문 상태로 매핑하고, `READY`인 행만 조건부 UPDATE했습니다.
- 정기 결제가 `PAID`로 확인되면 다음 예약이 있는지 조회하고, 없을 때 생성을 요청했습니다.

[배치 구현](https://github.com/juhyeon2398/soldeskProject2/commit/d6a068f) · [다음 예약 연결](https://github.com/juhyeon2398/soldeskProject2/commit/e8a419f)

### 실제 결제 시각 기준의 다음 예약일 계산

배치 실행 시각에 따라 예약 기준일이 달라지지 않도록, 저장된 결제 시각을 기준으로 다음 예약일을 계산했습니다.

- 완료 주문의 `order_paydate`를 읽어 `LocalDateTime`으로 변환했습니다.
- 해당 시각에 `plusDays(31)`을 적용하고 예약 시각을 자정으로 맞췄습니다.
