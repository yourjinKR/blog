**사용자 모드와 커널 모드는 CPU가 허용하는 실행 권한 수준이 다릅니다.** 사용자 모드는 애플리케이션의 직접적인 시스템 접근을 제한하고, 커널 모드는 운영체제가 자원과 하드웨어를 관리할 수 있는 권한을 제공합니다.

- **사용자 모드**: 일반 애플리케이션이 실행되며, 특권 명령 실행이나 보호된 커널 메모리에 대한 직접 접근이 제한됩니다.
- **커널 모드**: 스케줄링, 메모리 관리, 장치 제어 등 운영체제 작업을 수행하며 특권 명령을 실행할 수 있습니다.

애플리케이션은 파일 읽기 같은 작업을 **시스템 콜**로 요청합니다. CPU가 정해진 진입점을 통해 커널 모드로 전환하면 커널이 권한과 인자를 검사해 처리하고 사용자 모드로 돌아갑니다. 이 경계는 애플리케이션의 오류가 시스템 전체를 손상시키는 것을 막기 위해 필요합니다.

> [!QUESTION]- 일반 함수 호출과 시스템 콜은 무엇이 다른가요?
> 일반 함수 호출은 보통 같은 권한 수준에서 코드 실행 위치만 바꿉니다. 시스템 콜은 커널 서비스를 요청하기 위해 권한 경계를 넘으며, 검증과 모드 전환 등의 비용이 발생합니다.

> [!QUESTION]- 커널 모드로 들어가는 계기는 시스템 콜뿐인가요?
> 아닙니다. 타이머·장치 인터럽트나 Page Fault 같은 예외도 커널 핸들러로 제어를 넘길 수 있습니다. 이미 커널 모드에서 발생했다면 사용자 모드에서 커널 모드로의 전환은 추가로 일어나지 않습니다.

> [!QUESTION]- root나 관리자 권한으로 실행하면 커널 모드에서 동작하나요?
> 아닙니다. 계정의 권한과 CPU 실행 모드는 다른 개념입니다. 관리자 프로세스도 일반 코드는 사용자 모드에서 실행하며, 커널 서비스를 이용할 때 시스템 콜 경로를 거칩니다.
