# 포트폴리오

## OAuth2 임시 상태와 API 인증 분리

OAuth2 요청 객체 전체를 쿠키로 전달하던 방식을 바꾸고, 로그인 시작과 콜백 사이의 임시 상태만 세션에 저장하도록 구성했습니다.

- `HttpSessionOAuth2AuthorizationRequestRepository`에 요청 상태 저장을 위임했습니다.
- 콜백 처리 후 임시 Authorization Request를 제거했습니다.
- API의 JWT Access Token·Refresh Token 인증 흐름은 유지했습니다.

## OIDC·SSM 기반 배포 구성

GitHub Actions의 장기 PEM 키와 직접 SSH 접속 의존을 줄이기 위해, 기존 JAR·systemd 배포 절차에 OIDC와 SSM Run Command를 연결했습니다.

- Actions는 OIDC 임시 권한을 사용하고, 빌드한 JAR는 S3로 전달했습니다.
- EC2는 SSM 명령으로 산출물을 받아 기존 배포 스크립트를 실행하도록 구성했습니다.
- SSM 실행 상태와 EC2 내부 health check를 확인해 빌드 완료와 애플리케이션 기동을 구분했습니다.

[구현 PR](https://github.com/matchuri/backend/pull/75)


## 모듈 경계와 트랜잭션 설계

도메인마다 데이터 변경 책임을 갖도록 백엔드를 8개 Gradle 모듈로 나눴습니다. 팀 규모에 맞춰 단일 DB·JAR 배포는 유지했습니다.

- 다른 도메인의 Repository 직접 참조를 공개 조회 계약과 이벤트로 교체했습니다.
- 회원 탈퇴·그룹 정리처럼 함께 완료해야 하는 업무는 동기 이벤트로 같은 트랜잭션에서 처리했습니다.
- SSE 알림은 커밋 후 전달하고, 전송 시점에 수신 자격을 확인하도록 분리했습니다.
