# 기본

## 프로젝트에 대한 전반적인 소개

프로젝트 노크인은 생활패턴과 선호조건을 기반으로 서로 잘 맞는 룸메이트를 찾을 수 있도록 돕는 매칭 플랫폼입니다.

저는 백엔드 개발자로서 게시글 등록 및 조회 기능, 채팅 요청부터 1:1 채팅방 생성까지의 기능, 그리고 생활패턴과 선호조건을 기반으로 한 매칭 점수 계산 기능을 담당했습니다.

특히 매칭 점수는 온보딩 과정에서 수집한 사용자 정보를 바탕으로 서로의 생활패턴과 선호도를 비교하여 적합도를 계산하도록 구현했습니다.

# 포트폴리오

## 양방향 차단 조건과 인덱스로 게시글 조회 성능 개선

### 어떤 문제를 해결했고 어떻게 95%의 성능 개선을 달성했나요?

MVP 개발 이후 로컬 환경에서 부하 테스트를 진행했습니다. 그 과정에서 게시물 피드가 다른 API에 비해 성능이 좋지 않은 것을 확인 할 수 있었습니다. 이후 애플리케이션 레벨에서 DataSourceProxy 통해 실행 속도를 측정했고  DB 쿼리 자체에 병목이 있는 것을 파악했습니다. DB 실행 계획으로 파악해본 결과 양방향 차단 여부를 검증하는 과정에서 차단, 피차단 여부를 OR로 검증하고 있었고 이를 각각의 AND 연산으로 수정하는 쿼리 튜닝을 통해 옵티마이저가 인덱스를 정상적으로 타도록 유도하였고 그 결과로 성능 개선을 달성할 수 있었습니다.  

### 부하 테스트의 데이터 규모와 서버 환경은 어떻게 구성했나요?

로그인한 사용자의 게시글 검색 API가 차단 쿼리와 인덱스 변경 전후에 얼마나 달라지는지 확인했습니다. 테스트 데이터는 시드 설정을 1,000으로 고정했고, 실제 DB에는 회원 2,004명, 게시글 1,002건, 차단 관계 1,001건이 들어갔습니다.

로컬 장비에서 Java 21로 Spring Boot 서버를 실행하고, 테스트 프로필의 H2를 사용했습니다. 같은 장비에서 nGrinder Agent 1대로 가상 사용자 10명과 30명 조건을 각각 실행했습니다. 사용자당 100회씩 요청하고 변경 전후 각 조건을 3번 반복해서, 워밍업을 제외하고 총 2만 4천 건을 측정했습니다. 결과는 이 로컬 환경에서의 변경 전후 차이로 해석했습니다.

> [!question] 그렇게 할 경우 결과가 부정확하지 않나요?
> 맞습니다. 다만 이와 같이 진행한 이유는 앞서 말씀 드린 쿼리 개선과 같이 1차적으로 해결 할 수 있는 문제들을 먼저 처리하자는 팀원 간 합의가 있었고 이와 같은 경우에는 로컬 환경에서 충분히 관측 가능하다고 판단했습니다. 말씀해주신대로 더 정확한 측정을 위해 추후에는 요청 기기와 서버 기기를 분리하는 등 프로덕션 형태와 유사한 환경을 재구축하여 다시 테스트할 계획입니다.  

%%%%
### 30 VU는 무엇이며 동시 요청 30개와 같은 의미인가요?

VU는 가상의 유저 인스턴스 입니다. VU의 수만큼 동시 요청이 동일하게 발생하지는 않으며 같은 30 VUser라도 테스트 시간, 응답 시간, Think Time 등에 따라 총 요청 수는 크게 달라질 수 있습니다.  

### 24,000건의 요청은 어떻게 집계했나요?

인증 게시글 검색 API를 가상 사용자 10명과 30명 조건에서 각각 테스트했습니다. 가상 사용자 한 명당 100번씩 요청했기 때문에 10명 조건은 한 회에 1,000건, 30명 조건은 한 회에 3,000건입니다. 두 조건을 각각 3회 반복해서 변경 전 12,000건, 변경 후 12,000건으로 총 24,000건을 집계했습니다. 워밍업과 추가 지속 관측은 별도로 기록했습니다.

실행이 끝날 때마다 nGrinder Agent의 요청별 CSV를 세고, 성공·오류 건수가 Controller 집계와 일치하는지 확인했습니다. 인증 검색은 성공할 때마다 검색 이력이 한 건씩 저장되는 흐름이라, DB에서 이력 증가량도 대조했습니다. 본 측정 12회에서 총 24,000건이 성공했고 오류는 0건이었습니다.

### 3회 테스트 중앙값을 선택한 이유는 무엇인가요?  

한 번만 실행하면 그 결과가 반복해서 나오는지 알기 어려워서, 10 VU와 30 VU 조건을 변경 전후 각각 3번씩 실행했습니다. 서버와 nGrinder가 같은 장비에서 돌아갔기 때문에 호스트 자원 사용이나 JVM 실행 상태에 따라 회차별 편차가 생길 수 있었습니다. 그래서 유난히 빠르거나 느린 한 회차가 대표값에 미치는 영향을 줄이려고 중앙값을 썼습니다. 예를 들어 개선 후 30 VU에서 회차별 p95가 141.76, 130.13, 119.78ms였고, 가운데 값인 130.13ms를 보고했습니다.

> [!QUESTION]- 3번이면 충분한가요?
> 당시에는 동일한 로컬 조건에서 변경 전후 차이와 회차별 편차를 확인하는 데 사용했습니다. 3회 중앙값으로 개선 효과의 통계적 유의성까지 판단하기는 어렵습니다. 재현성을 더 확인하려면 각 실행의 측정 시간을 늘리고, 변경 전후의 실행 순서를 번갈아 가며 반복하겠습니다.

### OR 조건이 기존 인덱스 활용에 어떤 영향을 주는가요?

조건이 많아질 때 AND 연산자는 탐색 후보를 빠르게 줄일 수 있는 반면에 OR는 그렇지 못합니다.

## 성능 관측

### AOP를 활용한 실행 시간 계측 구조 구현 방식에 대해 설명해주세요

우선 API 경계와 가장 가까운 계층인 Service 경계에서 메서드 실행 시간을 측정했습니다.  
이를 위해 package를 범위로 잡아 메서드를 실행하도록 했습니다.  

또한 service 패키지 내부에는 없지만 메서드 실행 시간이 필요한 경우를 고려하여  
커스텀 어노테이션을 선언하여 해당 어노테이션이 붙은 메서드 또한 실행 시간이 계측되도록 만들었습니다.  

### Spring AOP 동작원리와 한계에 대해 설명해주세요

![[Spring AOP란 무엇이며, 어떤 상황에서 사용하나요#^260abd]]

Proxy의 대표적인 한계점은 [[Spring AOP#self-invocate 문제|self-invocate 문제]] 입니다. Spring은 요청시 프록시 객체로 가로챈다.  
그러나 `this.method()` 방식으로 자기 호출을 수행한다면 프록시로 가로채지지 않는다.  
그렇기에 내부 메서드를 자기 참조하는 방식으로 호출한다면 AOP가 동작하지 않는다.  

### DataSourceProxy를 사용한 이유를 설명해주세요

- [[DataSource proxy#Hibernate 로깅과 비교|Hibernate 로깅과 비교]]: Hibernate 로깅은 ORM 영역, DataSource는 JDBC 영역이기에 DB 계측에 더욱 적합하다고 생각했습니다. 그 이유로는 대표적으로 JPA의 1차 캐싱과 같은 동작으로 인해 DB로부터 쿼리가 요청되지는 않지만 로그 상으로는 여러 쿼리가 로깅되기에 실제 DB 요청과 차이점이 있습니다.  
- [[DataSource proxy#P6Spy와 비교|P6Spy와 비교]]: 레퍼런스가 많고 표준적 라이브러리라고는 알고 있으나 DataSourceProxy는 설정값 기반이 아닌 Java 코드를 기반으로 구현 가능하여 기존에 익숙한 개발 언어 환경에서 잘 활용할 수 있다고 생각하여 채택했습니다. 

### BeanPostProcessor의 동작 시점과 역할은 무엇인가요

[[BeanPostProcessor]]는 빈 처리기로 Bean이 Spring ApplicationContext에 저장되기 전후에 동작합니다.  
전 후 적용 시점은 구현 메서드를 통해 제어합니다.  

### DataSource를 직접 Bean으로 등록하지 않은 이유는 무엇인가요

DataSource를 직접 Bean으로 등록하지 않은 이유는 기존 Spring에서 제공하는 설정값을 그대로 활용하기 위해서 입니다.

## 공통 응답

기존 팀 프로젝트의 공통 응답 처리 구조를 검토하면서 Spring MVC의 반환값 처리 과정과 HTTP 응답 커밋 시점을 디버깅으로 추적했습니다. `RequestResponseBodyMethodProcessor` 확장 구현에서 본문 작성 이후 상태 코드를 설정하는 구조적 문제를 확인했고, 3xx 리다이렉션 및 HTTP 조건부 요청 처리의 필요성을 구분했습니다. 이후 상태 코드 변경에 필요한 부분만 `ResponseBodyAdvice`로 분리하는 대안을 실습했습니다.

**프로젝트 구현 방식**

```java
public class CustomRequestResponseBodyMethodProcessor extends RequestResponseBodyMethodProcessor {  
    public CustomRequestResponseBodyMethodProcessor(List<HttpMessageConverter<?>> converters) {  
        super(converters);  
    }  
  
    @Override  
    public void handleReturnValue(@Nullable Object returnValue, MethodParameter returnType, ModelAndViewContainer mavContainer, NativeWebRequest webRequest) throws IOException, HttpMediaTypeNotAcceptableException, HttpMessageNotWritableException {  
        super.handleReturnValue(returnValue, returnType, mavContainer, webRequest);  
        CommonResponse<?> httpEntity = null;  
        if (returnValue instanceof CommonResponse response) {  
            httpEntity = new CommonResponse<>(response.getBody(), response.getStatus(), response.getError());  
        }  
  
        ServletServerHttpRequest inputMessage = createInputMessage(webRequest);  
        ServletServerHttpResponse outputMessage = createOutputMessage(webRequest);  
        HttpHeaders outputHeaders = outputMessage.getHeaders();  
  
        if (httpEntity instanceof CommonResponse<?> responseEntity) {  
            HttpStatusCode returnStatus = responseEntity.getStatus();  
            outputMessage.getServletResponse().setStatus(returnStatus.value());  
            if (returnStatus.value() == HttpStatus.OK.value()) {  
                HttpMethod method = inputMessage.getMethod();  
                if ((HttpMethod.GET.equals(method) || HttpMethod.HEAD.equals(method)) && isResourceNotModified(inputMessage, outputMessage)) {  
                    outputMessage.flush();  
                    return;  
                }  
            } else if (returnStatus.is3xxRedirection()) {  
                String location = outputHeaders.getFirst(HttpHeaders.LOCATION);  
                if (location != null) {  
                    saveFlashAttributes(mavContainer, webRequest, location);  
                }  
            }  
        }  
    }  
  
    private boolean isResourceNotModified(ServletServerHttpRequest request, ServletServerHttpResponse response) {  
        ServletWebRequest servletWebRequest =  
                new ServletWebRequest(request.getServletRequest(), response.getServletResponse());  
        HttpHeaders responseHeaders = response.getHeaders();  
        String etag = responseHeaders.getETag();  
        long lastModifiedTimestamp = responseHeaders.getLastModified();  
        if (request.getMethod() == HttpMethod.GET || request.getMethod() == HttpMethod.HEAD) {  
            responseHeaders.remove(HttpHeaders.ETAG);  
            responseHeaders.remove(HttpHeaders.LAST_MODIFIED);  
        }  
  
        return servletWebRequest.checkNotModified(etag, lastModifiedTimestamp);  
    }  
  
    private void saveFlashAttributes(ModelAndViewContainer mav, NativeWebRequest request, String location) {  
        mav.setRedirectModelScenario(true);  
        ModelMap model = mav.getModel();  
        if (model instanceof RedirectAttributes redirectAttributes) {  
            Map<String, ?> flashAttributes = redirectAttributes.getFlashAttributes();  
            if (!CollectionUtils.isEmpty(flashAttributes)) {  
                HttpServletRequest req = request.getNativeRequest(HttpServletRequest.class);  
                HttpServletResponse res = request.getNativeResponse(HttpServletResponse.class);  
                if (req != null) {  
                    RequestContextUtils.getOutputFlashMap(req).putAll(flashAttributes);  
                    if (res != null) {  
                        RequestContextUtils.saveOutputFlashMap(location, req, res);  
                    }  
                }  
            }  
        }  
    }  
  
    @Override  
    public boolean supportsReturnType(MethodParameter returnType) {  
        return CommonResponse.class.isAssignableFrom(returnType.getParameterType());  
    }  
}
```

**실습한 내용**

```java
@RestControllerAdvice
public class CommonResponseAdvice implements ResponseBodyAdvice<Object> {

    @Override
    public boolean supports(MethodParameter returnType, Class<? extends HttpMessageConverter<?>> converterType) {
        return CommonResponse.class.isAssignableFrom(returnType.getParameterType());
    }

    @Override
    public @Nullable Object beforeBodyWrite(@Nullable Object body, MethodParameter returnType,
                                            MediaType selectedContentType,
                                            Class<? extends HttpMessageConverter<?>> selectedConverterType,
                                            ServerHttpRequest request, ServerHttpResponse response) {

        if (body instanceof CommonResponse<?> commonResponse) {
            response.setStatusCode(HttpStatusCode.valueOf(commonResponse.status()));
        }

        return body;
    }
}
```
