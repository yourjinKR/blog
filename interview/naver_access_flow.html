www.naver.com에 접속할 때 일어나는 과정

(브라우저에 URL을 입력하고, 화면이 표시되기까지의 전체 흐름)

1

URL 입력

사용자가 브라우저 주소창에 www.naver.com을 입력하고 엔터를 누릅니다.

⌕   www.naver.com
브라우저는 먼저 URL과 캐시, HSTS 등의 정보를 확인합니다.
2

DNS 조회 (도메인 → IP)

브라우저는 www.naver.com의 IP 주소를 알아내기 위해 DNS에 질의합니다.

💻
내 PC
⇄
🗄️
DNS 서버
www.naver.com → IP 주소
캐시가 없다면 로컬 DNS → 루트 → .com → 권한 DNS 순으로 재귀적/반복적 조회가 진행될 수 있습니다.
3

TCP 연결 (3-way handshake)

확인한 IP 주소의 서버와 통신하기 위해 TCP 연결을 수립합니다.

클라이언트SYN서버
클라이언트SYN + ACK서버
클라이언트ACK서버
TCP는 이후 데이터를 신뢰성 있게 전달하기 위한 연결 지향 통신 기반을 만듭니다.
4

TLS 핸드셰이크 (HTTPS)

HTTPS를 사용하므로 TCP 연결 후 TLS 핸드셰이크를 수행해 암호화 통신을 설정합니다.

브라우저는 서버 인증서를 CA 신뢰 체인으로 검증하고 세션 키를 합의합니다.
5

HTTP 요청 전송

TLS 연결이 완료되면 브라우저는 HTTP 요청을 서버로 보냅니다.

6

서버 요청 처리 (백엔드)

프론트 서버 또는 로드 밸런서가 요청을 적절한 애플리케이션 서버로 전달하고 백엔드가 요청을 처리합니다.

🛢️

Redis, RDB 등
실제 내부 아키텍처는 훨씬 복잡할 수 있으며, 여기서는 백엔드 처리 흐름을 단순화했습니다.
7

8

9

브라우저 렌더링 과정

브라우저는 받은 HTML을 파싱하고, 필요한 CSS·JavaScript·이미지·폰트 등을 추가 요청합니다.

10

웹 페이지 화면 표시

필요한 리소스를 해석하고 화면을 구성하면 사용자가 네이버 페이지를 볼 수 있습니다.

11

페이지가 표시된 후에도 검색, 클릭, API 호출 등에 따라 추가 HTTP 요청과 응답이 계속 발생합니다.

12

연결 종료 (또는 유지)

연결을 더 이상 사용하지 않으면 TCP 연결을 종료할 수 있습니다. 반대로 Keep-Alive로 일정 시간 유지할 수도 있습니다.

클라이언트FIN서버
클라이언트ACK서버
클라이언트FIN서버
클라이언트ACK서버
HTTP/3는 TCP가 아니라 QUIC(UDP 기반)을 사용하므로 연결 과정이 다릅니다.
한 줄 요약
브라우저에 www.naver.com을 입력하면, DNS로 IP를 찾고 → TCP/TLS로 연결한 뒤 → HTTP 요청을 보내고 → 서버가 처리한 응답을 받아 → 브라우저가 렌더링하여 화면에 표시합니다.
